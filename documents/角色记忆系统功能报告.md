# RP-Hub 角色记忆系统功能报告

> 报告日期：2026-08-05  
> 依据：`assets/js/app.js`、`index.html`、`assets/js/local-embedding.js`、`assets/js/storage-repository.js`、Android 原生存储层代码及现有测试契约。

## 一、系统定位与组成

RP-Hub 的"角色记忆"由三个层次组成，全部按**角色（character uuid）隔离**，切换角色卡时互不串记忆：

| 层次 | 载体 | 作用 |
| --- | --- | --- |
| 长期记忆引擎 | 「记忆系统」页（侧边栏进入） | 自动把历史对话提炼/向量化，超出保留楼层后替代旧上下文 |
| 设定记忆 | 世界书（World Info） | 角色卡的常驻设定、关键词触发的知识条目（before_char / after_char / at_depth） |
| 主动检索能力 | 记忆工具 + 关键词工具 + 联网工具 | 让模型在上下文不足时主动调工具补信息 |

记忆引擎当前提供**两种互斥模式**：`总结模式`（classic）与 `向量模式`（vector），同一时间只能启用一种。UI 中已明确标注「总结模式即将弃用」，推荐新记忆走「向量模式 + 本地模型」，旧总结记忆可一键迁移。

---

## 二、两种记忆模式对比

| 维度 | 总结模式（classic） | 向量模式（vector） |
| --- | --- | --- |
| 记忆形态 | 每轮一条第三人称高密度总结 | 每轮拆成多个可检索的段落分片 |
| 生成方式 | 副模型（普通聊天模型）逐轮总结，可并发 | 嵌入模型（API 或本地）向量化 |
| 召回方式 | 不召回，固定替换 | 按当前输入相关度召回 Top-K |
| 保留楼层 | 10–40 楼（默认 20） | 30–80 楼（默认 50） |
| 超出保留楼层后 | 用户原文不动，AI 原文被该轮总结替换 | 有记忆覆盖的旧轮整段从上下文移除，相关分片按需带回 |
| 关键依赖 | 总结副模型 + API | 嵌入模型（API 或本地 ONNX） |
| 去重/幂等 | 按源消息 ID 去重 | 按 vectorChunkId + 内容指纹去重 |
| 状态 | 即将弃用 | 当前主推 |

## 三、向量模式工作流

### 1. 分片（Chunking）
每轮对话先按用户/AI 原文切分：
- 单段上限 `1800` 字（超长按句末标点/换行截断，继续切）；
- 相邻小段不足 `400` 字时合并；
- 每个分片通常包含「用户输入 + 角色回复」，带轮次号、序号、发言人、消息索引，生成唯一 `vectorChunkId`。

### 2. 嵌入（Embedding）
- **API 后端**：调用 OpenAI 兼容 `/embeddings` 接口（需配置向量嵌入模型）；
- **本地后端**：Transformers.js + ONNX Runtime WASM 端侧推理，主线程分批执行、每批让出事件循环。内置捆绑模型 `bge-small-zh-v1.5`（512 维，约 24MB）；`gte-small`、`multilingual-e5-small` 已登记但未捆绑。
- 批量补录：每批 16 条，每 4 批落盘一次。
- 维度一致性校验：新向量维度必须与已有记忆一致，否则报错并提示重建/切换模型后重新提取。

### 3. 存储与量化
嵌入向量不存浮点数组，而是 **Int8 量化**（max-abs 归一化到 [-127,127]）+ base64 + scale 系数压缩存储，运行期再还原为 Int8Array 供余弦相似度计算，显著降低 SQLite 体积。

### 4. 召回（Recall）
- 查询文本 = 最新一条用户输入 + 上几轮用户输入（最多带前 3 轮）；
- 对查询做嵌入，与全部分片做**余弦相似度**暴力扫描（每 512 条让出一次主线程）；
- 附加**中文 n-gram 词面匹配加分**（2–4 字滑动窗口，命中每词 +0.015，上限 +0.08）；
- 阈值：最低相关度 40%–70%（默认 50%），召回数 Top-K 10–20（默认 10）；
- **已保留在上下文的最近轮次会被排除**，避免和原文重复；
- 结果按相关度排序、按内容指纹去重，合并同一轮重复分片后注入。

### 5. 上下文注入
召回的向量记忆以 `<role_memory_vector_recall>` 块形式注入对话（插入深度固定为 1，即靠近最新对话），内部为 `<memory_fragment turn="…" similarity="…">` 结构，并附说明：这些是历史分片而非当前现场，只作背景参考。注入内容也会被排除在普通消息处理和关键词检索之外，防止污染后续记忆提取。

### 6. 上下文压缩
当对话总楼层超过保留楼层（默认 50）时，凡已有向量记忆覆盖（或在空轮日志 `emptyTurns` 中）的旧轮，其原始 user/assistant 消息会从发送给模型的上下文中整段移除，需要时由召回分片替代。

## 四、总结模式工作流

1. **逐轮总结**：副模型读取最近 4 轮作为背景，但只把明确标记的「最新一轮」作为总结目标；
2. **总结规范**：第三人称、保留新增信息/心理/关系/状态/时间线/秘密/未决事项，删除寒暄与空话，只输出正文；
3. **幂等**：按源消息 ID 生成 key，已总结过的轮次跳过，避免重复；
4. **补录并发**：1–10（默认 5），只影响速度不影响内容与顺序；
5. **压缩**：超保留楼层后，AI 原文替换为该轮总结，用户原文保留；统计页提供单条/总压缩率预测（`summaryCompressedBodyLength`），界面展示「原始字数 → 压缩后字数」。

---

## 五、自动补录与手动补录

- **自动巡逻（memory patrol）**：开启记忆引擎、切换嵌入/总结模型、切换角色、对话更新后自动触发；
- **空闲等待**：角色正在生成回复时暂停补录，等待对话空闲后再继续，并在有新楼层时自动重扫；
- **手动补录**：「补录记忆」按钮可强制为全量历史补建记忆，支持中途停止；
- **空轮记录**：提取后无有效内容的轮次记入 `emptyTurns` 日志，下次跳过，避免反复空扫；
- 删除/编辑历史消息时，相关记忆会同步清理（`filterMemoriesAsync` / `removeMemoriesForConversationTurn`）。

## 六、主动检索工具（模型侧）

启用后模型可在回复前主动调用工具，均支持 `add`（追加结果）与 `cover`（替换旧结果）两种上下文管理语义：

| 工具 | 类型 | 用途 |
| --- | --- | --- |
| 向量记忆主动检索 `tool_memory` | vector_memory | 检索向量记忆，找旧剧情/设定/关系/物品来历/用户暗指内容 |
| 关键词检索 `tool_grep` | keyword_dialogue | 在当前对话原文中按关键词抓取原句片段 |
| Tavily 联网搜索 `tool_web` | web_search | 补充作品设定、同人资料、冷门角色、最新信息 |

另有「主动程度」设置（强制 / 积极 / 自适应）控制模型调用工具的倾向。

## 七、数据存储与迁移

- 存储位置：Android 端经 `NativeStoragePlugin` 写入 SQLite（`kv_store` 表），键为 `rp_hub_memories_<uuid>`（向量）与 `rp_hub_classic_memories_<uuid>`（总结），按角色隔离；Web 端走 IndexedDB 兼容层。
- 密钥安全：含 API Key 的配置单独走 `secret` 存储。
- 导出/导入：两种模式分别导出 JSON（总结模式带 `type: rp-hub-summary-memories` 标识），导入时按 key/指纹去重；支持一键「清空当前模式记忆」。
- 迁移：`总结记忆 → 向量` 一键迁移（离线可用，无需 API），迁移分片标记 `migratedFromClassic` 与 `vectorChunkId=classic:<turn>`，重复迁移幂等。

## 九、观察与风险点

1. **总结模式进入弃用通道**：UI 已提示新记忆走向量模式 + 本地模型，老用户需注意迁移入口；
2. **向量召回为全量暴力扫描**：分片多时耗时线性增长，虽每 512 条让出事件循环，超大数据量下仍可能造成卡片顿；本地嵌入目前是主线程原型，未使用 Web Worker；
3. **嵌入模型变更不兼容**：维度不一致会直接报错，需要重建向量记忆或切换后重新提取；
4. **记忆与聊天编辑联动**：删改历史消息会清理相关记忆，这是有意的数据一致性设计，但也意味着编辑历史会"丢失"已生成的记忆，需要自动重扫恢复；
5. **错误/中断的回复不计入记忆轮次**（2026-08-05 起），只展示不进入模型上下文与记忆，避免把失败的回复当成剧情事实。

## 十、图谱功能评估与设计（新增）

### 1. 现状结论

项目当前**没有任何图谱或可视化基础设施**：`package.json` 与 `assets/vendor` 中没有 d3 / vis.js / cytoscape 等图库，记忆页只有列表与检索，`app.js` 中也无图计算代码。但**数据基础已经具备**，做图谱不需要改记忆引擎：

- 每个分片已有 `id / turn / sequence / vectorChunkId / paragraph / summary / sourceText / sourceRole / sourceName / timestamp / embedding / contentFingerprint`；
- 已实现 `cosineSimilarity()`（分片间相似度可直接复用）；
- 已实现 `extractVectorQueryTerms()` / `getVectorLexicalMatch()`（关键词/实体共现可复用）；
- 图谱是"查看层"，只读分片数据，不触碰召回与补录逻辑，**风险低**。

### 2. 节点与边的设计

| 元素 | 定义 | 依据 |
| --- | --- | --- |
| 节点 | 每个向量记忆分片 | `id`、内容、轮次、时间 |
| 语义边 | 两分片 embedding 余弦相似度 ≥ 阈值（如 0.65–0.75，可调） | 现有 `cosineSimilarity()` |
| 轮次边 | 同一轮内分片串联；相邻轮次衔接 | `turn / sequence` |
| 实体边 | 共享关键词/命名实体共现（人、物、地点） | 复用 `extractVectorQueryTerms()` 做共现词 |
| 边强度 | 相似度或共现次数 | 决定线的粗细/透明度 |

节点大小/颜色可映射轮次新旧或"最近召回命中数"（后者依赖动态管理阶段的访问统计）。

### 3. 渲染方案（手机端约束）

- **首选**：原生 `<canvas>` + 自写力导向布局（斥力 + 弹簧 + 向心力），几百节点规模在移动端可流畅运行，零新增依赖，符合全离线打包风格；
- **备选**：vendored 轻量图库（如 `d3-force` 单模块或 cytoscape.js 精简构建），需评估 APK 体积增量；
- **性能**：全量 N×N 相似度只在首次/手动刷新时计算，结果缓存边表；计算放 Web Worker，避免卡主线程（本地嵌入目前就在主线程，图计算不应再叠加）。

### 4. 交互设计

- 记忆页向量模式新增「检索 / 图谱」切换（复用现有向量记忆检索面板位置）；
- 图谱支持缩放/平移/拖拽节点；点击节点弹出分片全文与所属轮次；
- 筛选：关键词、轮次范围、最低相似度、只看有边的节点；
- 与检索联动：在"向量记忆检索"命中后，可一键在图谱中高亮对应节点及其一跳邻居；
- 图例说明语义边/轮次边/实体边的含义。

### 5. 边表缓存

边是派生数据，默认不落库；仅在需要时缓存到 `memory_graph_<uuid>` 键并带版本号，分片增删（`_memoriesLoaded` / 补录 / 清空 / 删消息联动）时失效重建。

### 6. 结论

**可行性高、建议先做。** 它不改变记忆引擎行为，纯前端查看层；主要工作量在力导向布局与 N² 相似度计算的性能控制，两者都有成熟的低成本解法。

## 十一、动态记忆管理评估与设计（新增）

### 1. 现状结论：确实"只增不改"

用户观察准确。当前向量记忆的生命周期基本是 **append-only + 简单去重**：

- 新增：补录巡逻持续追加分片（按 `vectorChunkId` / 内容指纹去重）；
- 删除：仅手动清空、删改聊天记录时联动清理、空轮跳过；
- 无合并：`mergeRepeatedTurnVectorMemories` 只在**召回注入时**临时合并同轮分片，不落库；
- 无强度/衰减：分片没有 `importance / accessCount / lastAccessedAt`，召回只看余弦相似度 + 词面加分（导出导入时还会丢弃 `importance` 字段）；
- 无淘汰：记忆只增不减，时间越长越臃肿。

存储与检索效率也有两处真实瓶颈：

1. **整块重写**：`saveMemoriesNow()` 每次把全部分片序列化成一个大 JSON 写入 SQLite `kv_store`（`compactMemoriesForStorageAsync` → `dbSet` 整键覆盖），分片上万后每次保存都是全量重写；
2. **O(N) 全量召回**：`scoreVectorMemories()` 每次对话都重新嵌入查询、遍历全部分片算余弦，数据量增长后延迟线性上升。

### 2. 目标能力拆解

用户想要的是"记忆会自己整理"——对应业界称为 **记忆巩固（consolidation）+ 遗忘曲线（decay）+ 存储分层** 的能力。拆成四块：

#### A. 记忆强度与衰减（相关度动态化）

- 每个分片新增元数据：`importance`（初始 1.0）、`accessCount`、`lastAccessedAt`、`createdAt`、`status`；
- 召回命中时提升强度（`accessCount++`、`importance` 微升、`lastAccessedAt` 更新）；
- 长期未命中按遗忘曲线衰减（如每 30 天 ×0.9）；
- 综合分：`vectorScore = cosine + lexicalBoost + importanceBoost + recencyBoost`，用于召回排序与后续淘汰；
- 导出格式升级为 v2 并保留这些字段（当前导入代码会删掉 `importance`，需改）。

#### B. 自动合并（记忆凝练）

- 在对话空闲时运行"整合巡逻"：对语义高度相似的分片簇（相似度 ≥ 合并阈值，如同主题重复描述、跨轮复述同一事件）调用副模型（复用总结模式副模型）合并成一条"凝练记忆"，保留事实、关系、时间线；
- 旧分片标记 `status: superseded`（软删除），不做物理删除；
- 合并后的分片用凝练文本**重新嵌入**（平均向量会丢失细节，不推荐直接聚合 embedding）；
- 无副模型/离线时降级为"只标记候选、不执行"，或"保留最优分片、标注冗余"；
- **冲突保护**：同主题但事实矛盾的分片不合并，标记 `conflict` 供用户或模型裁决，防止把错误事实"洗"进新记忆。

#### C. 自动淘汰（遗忘）

- **安全优先，默认软删除**：淘汰候选进入"回收站"（`status: archived`），用户可查看/恢复，确认后才物理清理；
- 候选条件：强度低于阈值 且 长期未访问 且 与其他分片高冗余；`importance` 高的关键记忆永不自动淘汰；
- 提供「自动遗忘」总开关与手动「整理记忆」按钮，执行前预览将合并/删除的条目。

#### D. 高效存取

- **增量存储**：仿照现有 `chat_messages` 逐条行存储模式，为向量记忆建 `memory_fragments` 表（或按分片分块键），避免整块重写；
- **检索加速**：
  - 短期：按 `turn` 聚类过滤 + 缓存最近查询的 Top-K 结果；
  - 中期：语义簇质心索引（图谱边表反过来做预过滤：先找最近簇，再簇内精排），一次计算、图谱与检索两用；
  - 长期：评估 HNSW 式近邻库（需控制包体积与离线打包兼容）。
- **维护调度**：复用现有 patrol 机制，在补录完成后挂"整合 + 淘汰"阶段，支持 abort / 进度 / 并发；频控为"新增 N 轮"或"分片数超阈值"或"定期"触发，不做随对话高频跑。
- **审计**：所有自动改动写入 `memoryAuditLog`（合并/淘汰/恢复记录），可回溯。

### 3. 主要风险与边界

1. **自动删除的信任风险**：记忆是用户资产，静默删除会损害信任 → 必须软删除 + 回收站 + 审计 + 预览确认；
2. **合并成本**：依赖聊天模型，有 API 费用与延迟；离线只能降级；
3. **衰减调参**：衰减系数、合并阈值、淘汰阈值需要数据验证，默认值应保守（宁少删、多保留）；
4. **embedding 聚合陷阱**：合并后必须重新嵌入凝练文本，不能直接平均原向量；
5. **图谱与动态管理是两个独立系统**：图谱是查看层（低风险），动态管理是引擎层（高影响），应分开排期，避免一次改动面过大。

- 解析器移入 `memory-schema.js` 的 `parseFactResponse`，兼容直接 `{"facts":[...]}` / chat/completions 信封 / SSE 强制流式 / Markdown 围栏四种格式；
- `normalizeFact` 实体兼容 `attrs` 与 `attributes` 别名；
- 伏笔的剧情状态拆到独立字段 `plotStatus`（生命周期状态保持 `current`），并在 `loadMemoryFacts` 增加旧数据加载迁移（`status open/closed → plotStatus`）；

## 十三、记忆规则（本体 Schema）设计（新增）

### 1. 判断：方向正确，RP 记忆确实有近似封闭的本体

角色扮演对话的抽象记忆层高度收敛——时间线、角色、事件、关系网、状态、世界设定、伏笔/未决事项，确实像用户所说"相对固定"。给向量记忆定一套"规则"（结构化本体）能带来连锁收益：

- **召回精准**：按类型/实体/时间定向检索，替代纯相似度全量扫描；
- **天然去重与合并**：同一实体 + 同一事实 = 同一身份，可版本化，不再靠文本指纹猜；
- **图谱升级**：实体节点 + 类型化关系边 = 真知识图谱，比"文本分片相似边"有意义得多；
- **分层保留**：事件可滚入凝练，关系/秘密/伏笔长期保留；
- **与世界书互补**：世界书 = 静态设定（已结构化），动态记忆 = 剧情事实（补上结构化），两者口径统一。

### 2. 核心原则：结构化是"解释层"，不是"替代层"

最大的风险是信息丢失——RP 内容自由，固定 schema 装不下所有东西。因此采用**分层**：

- **L0 原始分片**：现有向量分片继续保留，作为"证据/原文"，永不删除；
- **L1 事实层**：结构化的 fact 作为 L0 的投影，每条 fact 必须引用来源 turn/分片 id，可重生成、可审计；
- **fallback**：无法归类的信息落入自由文本，不硬塞 schema。

### 3. 本体 Schema v1（角色扮演专用）

| 类别 | 形态 | 关键字段 | 保留策略 |
| --- | --- | --- | --- |
| 角色/物品/地点/组织实体 | 节点 | id、name、kind、attrs（身份/外貌/性格/能力/知识/秘密/目标）、status | 长期 |
| 关系 | 有向边 | from、to、kind（情侣/师徒/敌对/家人/同事…）、strength(0-1)、attitude、trust、status | 长期 + 阶段演化 |
| 事件 | 节点 | id、inStoryTime、realTurn、summary、participants[]、causes[]、results[] | 可滚入凝练 |
| 状态快照 | 事实 | subject、aspect（身体/精神/物品归属/能力/职位…）、value、changedFrom | 只留最新 + 版本历史 |
| 时空 | 事实 | currentTime、currentPlace、sceneTransitions[] | 当前值 |
| 剧情线/伏笔 | 节点 | summary、status(open/closed)、relatedEntities[] | 长期（未闭合） |
| 对话元信息 | 事实 | 已说/未说、隐瞒、误解、禁忌话题 | 长期 |

> **定稿对齐**：实体的静态属性（身份/外貌/性格等）由世界书与角色卡提供，**记忆不重复存储**；记忆层只记录动态变化与新增知识（如新习得的能力、新获得/失去的物品、新发现的秘密、关系强度变化）。详见第十四节。

示例（`schemaVersion: 1`）：

```json
{
  "schemaVersion": 1,
  "turn": 12,
  "facts": [
    {"id":"f:1","type":"entity","subject":"林晚","attrs":{"身份":"师姐","性格":"外冷内热"},"status":"current","sourceTurn":12},
    {"id":"f:2","type":"relation","from":"user","to":"林晚","kind":"师徒","strength":0.8,"status":"current","sourceTurn":12},
    {"id":"f:3","type":"event","id":"ev:042","inStoryTime":"第3天","summary":"林晚为救user受伤","participants":["林晚","user"],"status":"current","sourceTurn":12},
    {"id":"f:4","type":"state","subject":"林晚","aspect":"身体状况","value":"受伤(左臂)","status":"current","sourceTurn":12},
    {"id":"f:5","type":"plot","summary":"戒指来历未解","status":"open","sourceTurn":12}
  ]
}
```

### 4. 提取管线

- 每轮（或补录巡逻时，异步、不阻塞对话）由副模型按 JSON schema 抽取 facts，记录 `sourceTurn / sourceFragmentIds`；
- 抽取失败或离线时**降级**：只保留 L0 原始分片 + 词面实体标签（复用现有 `extractVectorQueryTerms()`），等有模型时再回填；
- 事实去重：同一 `(subject, type, key)` 视为同一事实，新值写新版本，旧值 `status=superseded`；
- 冲突：同事实不同值且无法判定新旧 → `status=conflict`，交由用户或模型裁决（衔接第十一节 C 的淘汰/冲突机制）。

### 5. 按规则召回

| 用户/模型需求 | 检索路径 |
| --- | --- |
| "她是谁 / 什么身份" | 实体节点 → attrs + 最近事实 |
| "我们关系现在怎样" | 关系边（user ↔ 角色）最新版本 |
| "上次发生了什么 / 去了哪" | 事件节点按 inStoryTime / realTurn 索引 |
| "他身体状况如何" | 状态快照最新值 |
| "还有哪些伏笔没收" | `status=open` 的剧情线 |
| 开放性问题 | 事实文本嵌入 + 图谱一跳扩展混合检索 |

召回结果按类别组装为 `<memory_facts>` 块注入上下文（延续现有 `<role_memory_vector_recall>` 的 XML 风格），并附来源轮次，让模型知道每条事实的证据出处。

### 6. 对存储/图谱/动态管理的叠加收益

- **存储**：nodes / edges / fact_versions 天然是逐条行存储，直接解决"整块重写"瓶颈（P3）；
- **图谱**：实体 + 类型化关系边 = 真知识图谱；P0 图谱的数据模型应预留 schema 升级位，先展示分片级视图，后切换到实体/关系视图；
- **合并**：按实体与剧情弧凝练，天然幂等（同一实体只归并一次）；
- **衰减/淘汰**：关系强度可衰减、事件可滚入凝练、关键实体与伏笔永不自动淘汰。

### 7. 风险与注意

1. 结构化抽取依赖聊天模型 → 离线只能降级，UI 需明示"结构化记忆需要在线模型"；
2. 固定 schema 有刚性 → 必须带 fallback 与 `schemaVersion` 可演进机制；
3. 抽取质量 → 每条 fact 保留来源引用，出错可追溯、可重建；
4. 成本/延迟 → 抽取走补录巡逻异步执行，不阻塞对话（与总结模式同一模式）。

> 结论：把「记忆规则/本体」定为整个向量记忆系统的数据骨架，P1–P3 都建立在它之上——召回、合并、淘汰、图谱、增量存储共享同一套 schema，而不是各自为政。

## 十四、定稿架构：静态世界书 + 差异式动态记忆

> 本节为定稿方案，第十至十三节为推演过程与评估，若与本节冲突，以本节为准。

### 1. 三层数据职责

| 层 | 载体 | 职责 | 是否变动 |
| --- | --- | --- | --- |
| 静态设定层 | 世界书 + 角色卡（description / personality / 开场白） | 角色身份、世界观、大纲，常驻注入 | 永不写入记忆，不复制 |
| 原始事件层 | 聊天历史（`chat_messages`） | 完整对话原文，事件与事实的源头 | 独立存储，记忆不复制全文 |
| 动态事实层 | 记忆系统（Schema v1） | 每轮相对上一轮的"差异账本" | 只存增量 |

### 2. 每轮只写四种增量

1. **事件**：发生了什么（参与者 / 因果 / 结果），带 `realTurn`（对话轮次）+ `inStoryTime`（剧情内时间）双时间戳；
2. **状态变化**：什么变了（身体 / 物品 / 能力 / 关系），只保留**最新值 + 版本链**（`changedFrom`），旧值标记 superseded；
3. **时间线**：事件按序索引，旧事件定期**滚入剧情弧总结（arc）**，细节归档，时间线只留里程碑；
4. **对话事实**：值得原话保留的台词（誓言 / 秘密 / 表白 / 威胁 / 身份确认），普通寒暄与复述不存。

关系变化并入状态与事件：关系强度、态度、信任度的变化作为状态变化记录。

### 3. 效率约束（不是仓库）

- **存储上界**：`O(实体数 + 事件数 + 剧情弧数)`，与对话长度脱钩；对话再长，记忆只长在真正的新信息上；
- **行存储**：`memory_facts / memory_relations / memory_events / memory_arcs` 分表存储，不做整块 JSON 重写；
- **向量按需**：实体 / 关系 / 状态 / 时间线走索引查询；仅开放性问题与 arc 摘要建立 embedding；
- **证据窗口**：原始分片仅作短期证据，提取并整合后进入归档 / 软删，可恢复但不占活跃存储；
- **召回摘要**：每次注入"当前状态 + 最近事件 + 相关关系 + 未决事项"的紧凑摘要，而不是批量相似分片让模型自行拼接。

### 4. 冷启动基线（待确认项）

- 选择角色 / 开新对话时，从**开场白**构建动态基线：时间线起点、初始场景（时间 / 地点）、初始状态、初始关系；
- 世界书内容不进入记忆（静态层唯一来源）；
- 按角色构建一次，清空记忆后重建，幂等；
- 离线降级：只切分开场白 + 词面标签，待有在线模型再回填结构化事实。

### 5. 图谱与 Schema 对齐

- 图谱目标形态：**实体 / 事件节点 + 类型化关系边**（真知识图谱），而非文本相似边；
- P0 先做分片级视图（低风险），数据模型预留实体 / 事件升级位；
- Schema v1 即动态事实 schema：实体只记动态变化，静态身份引用世界书，不重复存储。

### 6. 排期对齐

P0 图谱（查看层）→ P1 差异式事实层（Schema + 抽取 + 冷启动）→ P2 自动整理（roll-up / 淘汰 / 审计）→ P3 高效存取（行存储 + 索引）。
